# Developing Peacock

The maintainer's side of the repo: what lives where, how the pack is updated, how a version is cut.
Players should read the [README](../README.md); server admins the [server runbook](../server/README.md);
the reasoning behind every setting is in [DECISIONS.md](DECISIONS.md) and the phase history in [PLAN.md](PLAN.md).

The pack is managed with [packwiz](https://packwiz.infra.link). Mods are never committed —
`pack/mods/*.pw.toml` pins each one to an exact version and hash, and the installer fetches them.
Everything you can edit lives in `pack/`.

## Layout

```
pack/                 the packwiz pack — this is what gets installed
  pack.toml           name, versions, index hash
  index.toml          every file below, hashed (regenerate with `packwiz refresh`)
  mods/*.pw.toml      one file per mod (180; Spark, LuckPerms, Dynamic View, Noisium, Chunk Pregenerator server-only)
  shaderpacks/        Complementary Reimagined (the only shader; Euphoria Patcher builds the high/ultra variant from it)
  resourcepacks/      Fresh Animations (+Details, Objects, More Mob Variants), Optimized Bushy Leaves over Better Leaves, Fast Better Grass, rainbow's foliage, 3D Default, Cubic Sun & Moon,
                      Enhanced Boss Bars, xali's books/potions, Low On Fire — on by default (the order is in tools/gen-profiles.py)
  config/             shipped configs; `preserve = true` files are not overwritten on update
  defaultconfigs/          server configs copied into new worlds (Big Cannons: no block damage)
  config/defaultoptions/   first-launch options.txt + keybindings.txt (Default Options)
  patchouli_books/         The Settler's Almanac (in-game guide; tools/gen-almanac.py)
  kubejs/                  KubeJS: the Blueprint ladder (boss_tuning.js lifts the Radiation Director to boss stats), the capital economy
                           (capital_npcs.js framework, capital_services.js, capital_projects.js, steward.js, villager_trades.js), journals, bounty vouchers, welcome line, /peacock profile, caps and gates;
                           the capital: capital_wall.js (wall + gates, /peacock wall), capital_boards.js (the bounty board pavilion),
                           dead_capitals.js (far copies of the capital turn zombie);
                           metals.js (startup + server: alloys, metal blocks, sheets, villager metal trades, one tin/bronze/steel),
                           metal_gear.js (tools and armour in every metal), metal_uses.js (each metal's jobs), flint_hammer.js
  config/paxi/datapacks/peacock-ruins.zip  generated by tools/gen-ruins.py: every CTOV village as a ruin + the capital (a scattered large CTOV town)
  config/paxi/datapacks/peacock/  the pack's datapack (Paxi loads it above all mods): worldgen overrides, tags, recipe fixes,
                                  Bountiful pool overrides + the Archivist decree, loot tables, the Rust Belt structures
  peacock/launch.jar       pre-launch: packwiz sync + profile apply (kubejs/config/peacock-profile.json, else PEACOCK_PROFILE)
  peacock/profiles/<tier>/ potato | low | medium | high | ultra — *.keys files (one setting per line; a `[table]` line scopes the keys after it to that TOML table), generated by tools/gen-profiles.py
dist/Peacock-Prism.zip  the importable Prism instance (tools/build-instance.py) — committed so raw.githubusercontent.com serves it
instance/             Aaron's own Prism instance.cfg / mmc-pack.json, kept for reference only (dist/ supersedes it)
tools/                validate.py (CI), gen-profiles.py, gen-almanac.py, gen-ruins.py, gen-bounties.py, gen-rustbelt.py, build-launch.sh,
                      launch/Launch.java (source of launch.jar), data/journals.json (the found writings)
server/               pterodactyl/ (egg + install script), start.sh (bare metal), server.properties, JVM args
pack/peacock-server/  server-only config overrides, shipped by the pack, copied over the server root on start
docs/                 PLAN.md (phases), DECISIONS.md (why things are the way they are), QUICKSTART.md and the
                      INSTALL-*.md guides (Modrinth, Prism, CurseForge)
```

## Generators

Several parts of the pack are generated; edit the generator, not the output, and commit both.

| generator | writes | from |
|---|---|---|
| `tools/gen-profiles.py` | `pack/peacock/profiles/<tier>/**.keys` | the TIERS table + Complementary's own presets (downloaded) |
| `tools/gen-almanac.py` | `pack/patchouli_books/peacock_almanac/` | the ENTRIES table; fails if a page exceeds its text budget |
| `tools/gen-ruins.py` | `pack/config/paxi/datapacks/peacock-ruins.zip` | CTOV's jar + its compat jars (downloaded, cached in `~/.cache/peacock`) |
| `tools/gen-bounties.py` | Bountiful pool overrides, the Archivist decree, rumour loot tables, `kubejs/config/journals.json` | `tools/data/journals.json` + the tables in the script |
| `tools/gen-rustbelt.py` | Rust Belt / nature / war-camp NBTs, structures and structure sets | the voxel functions in the script |
| `tools/gen-advancements.py` | the Peacock achievements tab (`data/peacock/advancements/**` in the pack datapack) | the boss table in the script (must match `kubejs/server_scripts/achievements.js`; `validate.py` checks), `tools/data/journals.json`, the ruin tag in `peacock-ruins.zip` — run after `gen-ruins.py` |
| `tools/build-launch.sh` | `pack/peacock/launch.jar`, then `dist/Peacock-Prism.zip` via `tools/build-instance.py` | `tools/launch/Launch.java` (needs a JDK ≥ 17) |
| `tools/build-instance.py` | `dist/Peacock-Prism.zip` — the importable Prism instance (instance.cfg, mmc-pack.json, launch.jar) | the constants in the script |
| `tools/gen-deposits.py` | every Geolosys deposit in the pack datapack (weights x10, small/normal/large variants, the deep layer); prints the `chunkSkipChance` to set | `tools/data/geolosys-deposits.json` (Geolosys' own definitions + the pack's) and the tables in the script |
| `tools/apply-profile.py` | a pack copy with one tier's `*.keys` baked into its config files (release workflow, CurseForge zips) | `pack/peacock/profiles/<tier>/` |

After any of them: `cd pack && packwiz refresh && cd .. && python3 tools/validate.py`.

## Server

Pterodactyl: import `server/pterodactyl/egg-peacock.json`, create a server from it, one
allocation (voice chat shares the game port). Every start syncs the pack from `main`.
Full runbook in [`server/README.md`](../server/README.md) — install, pregen, overrides, rollback;
bare-metal `server/start.sh` as the alternative. Server-only mods (Spark, LuckPerms) carry
`side = "server"` and never reach clients.

KubeJS on this pack (Rhino 2001) has traps `validate.py` cannot all see: `var` inside functions (no `const`/`let`
in blocks), no `Math.PI`/`Math.E`, `event.cancel()` last (it throws to end the handler), some vanilla methods are not
reachable by name (`level.getGameTime()` — use `level.getLevelData().getGameTime()`; `Entity.distanceTo`, `Direction.getStepX`
— work from `x`/`y`/`z`), a `Java.loadClass` result has no `isInstance` (use `instanceof`), and JDK immutable lists
from the game (`StructureStart.getPieces()`) must be copied into a `java.util.ArrayList` before Rhino can read them.
`validate.py` rejects the ones it can see. Compile scripts with a local Rhino before shipping.

## Updating the pack

```
cd pack
packwiz modrinth update <slug>        # or: packwiz update --all
packwiz refresh                        # rewrites index.toml + pack.toml hash
cd .. && python3 tools/validate.py     # must pass
```

Commit `pack/`, open a PR. CI re-runs `packwiz refresh` and fails if the index is stale.

Adding a mod: `packwiz modrinth add <slug>` (or `packwiz curseforge add <slug>`), then set
`side = "client"` in its `.pw.toml` if it is client-only. Three checks first, each learned the hard way:
- **Required dependencies.** Read the jar's `META-INF/mods.toml` for `mandatory = true` entries and make sure each
  mod id is in the pack — and before *removing* a mod, that nothing else requires it (Stoneholm was required by
  Create: Better Villagers; removing it stopped the server booting, 2026-10-19).
- **Registries.** A mod that registers anything (particles, items, blocks, sounds) must be on the server too,
  even if it is "client-only" on Modrinth: Forge matches the client's registries to the server's on join and drops
  the rest (Subtle Effects crashed on its first particle, 2026-10-20). A mod that does nothing on a dedicated
  server (Particle Rain) cannot be fixed that way.
- **Filenames.** No spaces in a `.pw.toml`'s `filename` (`validate.py` fails on them); rename it, and update any
  list that refers to it (resource pack lists in `tools/gen-profiles.py` and `config/defaultoptions/options.txt`).

### Releasing a version

Players on the Prism + `launch.jar` route (and Modrinth App players with the launch hook) sync from `main` on every
launch and never need a release; Modrinth App players without it re-download the rolling `.mrpack` (below).
Versioned releases are for the CurseForge App and bare-metal servers:

```
# bump version = "X.Y.Z" in pack/pack.toml, commit, then
git tag vX.Y.Z && git push origin vX.Y.Z
```

Between versions, `.github/workflows/mrpack.yml` rebuilds `Peacock.mrpack` on every push to `main` that touches
`pack/` and puts it on the `rolling` pre-release (tag force-moved), so the Modrinth App download linked from the
README (`releases/download/rolling/Peacock.mrpack`) is always current without tagging anything.

`.github/workflows/release.yml` builds `Peacock-Prism.zip` (the importable instance), `Peacock-X.Y.Z.mrpack`,
five `Peacock-X.Y.Z-curseforge-<tier>.zip` (one per hardware tier, profile baked in with `tools/apply-profile.py`)
and `Peacock-X.Y.Z-server.zip`, and attaches them to a GitHub release with the commit log as notes.
The Prism zip is also committed as `dist/Peacock-Prism.zip` so `raw.githubusercontent.com` serves it without a
release; `tools/build-launch.sh` rebuilds it whenever `launch.jar` changes. The
`.mrpack` embeds CurseForge-hosted mods as overrides (`--restrictDomains=false`), which is fine for our own
distribution but would be rejected by a public Modrinth listing — publishing there means swapping those
mods for Modrinth-hosted equivalents first.
