# Plan

Phases, each a small PR that is booted and tested before the next (seven so far; 1.0.0 is the end of Phase 7). The loop
throughout: launch → paste the log → the log becomes the next commit.

**Peacock is a server pack.** Design for a whole server from day one, not two players:
technology unlocks are **per player**, the economy and the world are shared, and the first
two players are simply the first two players. Anything that would only work for a couple
(house rules, "we'll just agree not to") is replaced by a mechanic.

### Phase 1b — Hardware profiles + cross-platform launcher  ✅ 2026-10-16
- Profiles named by hardware tier, not OS: `potato`, `low` (pack default since 2026-10-18; was `medium`), `medium`,
  `high`, `ultra` — `pack/peacock/profiles/<tier>/`, generated by `tools/gen-profiles.py`
  from the pack defaults and Complementary's own preset definitions (so they track the pack version).
  | profile | meant for | DH | shaders |
  |---|---|---|---|
  | `potato` | iGPU / hot / <16 GB | 96, DISABLED, 1 thread | off; CR Potato preset if enabled |
  | `low` | iGPU with headroom (Vega 8) | 128, FAKE, 1 thread | CR, Potato |
  | `medium` | fanless thin-and-light, 16 GB | 192, FAKE, 2 threads | CR, Medium |
  | `high` | laptop with a real GPU | 256, COMPLETE, 4 threads | CR + Euphoria, High |
  | `ultra` | desktop, dedicated GPU | 384, COMPLETE, 6 threads | CR + Euphoria, Ultra |
- Selection: `PEACOCK_PROFILE` environment variable in the Prism instance (superseded 2026-10-18 by the in-game
  `/peacock profile <tier>` command and `kubejs/config/peacock-profile.json`; the variable remains the fallback).
- Launcher: `pack/peacock/launch.jar` (source `tools/launch/Launch.java`, built by
  `tools/build-launch.sh`, Java 17 bytecode, no deps). Downloads the packwiz bootstrap if missing,
  syncs, applies the profile. A jar rather than a `.java` source file because Prism-downloaded
  runtimes are JREs without a compiler. Same command on macOS/Linux/Windows:
  ```
  "$INST_JAVA" -jar "$INST_MC_DIR/peacock/launch.jar" https://raw.githubusercontent.com/Nublys/peacock/main/pack/pack.toml
  ```
- Profiles are `*.keys` files (one setting per line, target file's syntax) applied **per setting** —
  mods rewrite their config files on every start, so whole-file hashes never match. A setting is
  written only if missing, still equal to what a profile last wrote (`peacock/.state.properties`),
  or — on first adoption — equal to any shipped profile's value.
  In-game edits are never overwritten (`PEACOCK_RESET=1` for one launch overrides this). Replaces the
  `preserve = true` dead end. `PEACOCK_OFFLINE=1` skips the sync.
- Retired `profiles/mac`, `profiles/linux`, `tools/apply-profile.sh`.
- **Test:** `PEACOCK_PROFILE=low` on the 5850U, `medium` on the Air; F3 FPS before/after; DH radius
  and shader preset match the table; switch the variable, relaunch, confirm; edit a setting in-game,
  relaunch, confirm it survives.

## Phase 4 — The boss ladder (per-player unlocks)  🟡 shipped 2026-10-17, untested in play
Implementation (`kubejs/startup_scripts/peacock_ladder.js` is the single table; `server_scripts/blueprints.js`
enforces; `client_scripts/blueprint_tooltips.js` explains; **Recipe Stages** added for per-player crafting):
- 15 rungs in 4 tiers: brass, recruiting, blasting, climate, cooking · trains, ships, trade, diesel, diving ·
  precision, netherite, cannons · arcane industry, ender logistics. Mutant Enderman dropped from the
  ladder; "frontier ore" became arcane industry (Enchantment Industry + Dragons Plus); Ender Guardian
  holds ender logistics.
- Every crafting-table recipe a rung gates (by output, output mod, or input) is wrapped at load into a
  `recipestages:stage`/`shaped_stage` recipe with stage `peacock_<rung>`: visible in EMI, refuses to craft
  without the stage. Everything staged is also place-gated; recruit hiring (emerald on a `recruits:*` mob)
  needs `peacock_recruiting`. Non-crafting recipes (Create mixing/pressing/sequenced assembly, smithing)
  cannot be staged — brass can be mixed by anyone, but nothing can be built from it.
- Blueprint item `peacock:blueprint{tech}`: boss death gives one to every player who damaged it and is
  within 128 blocks, plus one spare on the ground; right-click to learn. Charter: paper + key item +
  2/4/6/8 emerald blocks by tier (`peacock:charter/<rung>`).
- Switch `ladder` in `kubejs/config/peacock.json`. Not done: Almanac chapters opening per stage,
  villager trade reactions, FTB Teams sharing (all need play data first).
Unlocks are **per player**, tracked with Game Stages (already in the pack). Nothing is
server-wide: a player who has not recovered a technology cannot craft it, even on a server
where others have.

- **Blueprint item** (one item, NBT per technology). A boss drops **one Blueprint per
  participant** — every player who damaged it and is within range when it dies — plus one.
  Using a Blueprint grants that player the stage and consumes it. Blueprints are ordinary,
  tradeable items: knowledge spreads through the server's economy (sell it, gift it, loot it
  from a corpse). This is the story — civilization recovers by sharing what it recovers.
- **Enforcement:** Recipe Stages (per-player recipe locks on 1.20.1 Forge, EMI/JEI hides
  locked recipes) if its 1.20.1 build proves solid; otherwise KubeJS cancels crafting/
  assembly for players without the stage and shows a "requires" tooltip. Either way the
  gated *blocks* also check stage on place/use, so a crafted item handed to an unstaged player
  is not a bypass.
- **Item Stages** (optional) to hide locked items in EMI until the stage is earned — decide
  after seeing how discoverable the ladder feels without it.
- **Tier 1 first** (Mutant Zombie → brass, Mutant Skeleton → recruiting, Mutant Creeper →
  gunpowder tech, Torte → advanced cooking) + the fallback "charter" recipe (expensive,
  emerald-priced, so a stalled boss never blocks a player).
- **Boss availability at server scale:** structure-bound bosses (Mowzie's, Cataclysm,
  Illager fortresses) are one per structure, so spacing (Phase 2) decides supply; late
  tiers use summonable bosses (Respillaged totems, Incendium's Hovering Inferno) so a full
  server is never waiting on worldgen.
- **Patchouli *Settler's Almanac*** — shipped 2026-10-17 (`pack/patchouli_books/peacock_almanac`,
  generated by `tools/gen-almanac.py`; handed out on first join by `kubejs/server_scripts/almanac.js`).
  Phase 4 adds per-player locked chapters that open with the player's stage.
- **Villager reactions** per town (stage-gated trades appear once *any* resident player has
  the stage — towns remember who taught them).
- **FTB Teams (optional, later):** if players want shared progression inside a group,
  Blueprint use can grant the stage to the whole team. Default is per player.
- Then Tiers 2–4.
- **Test:** two accounts on the server — player A kills a Mutant Zombie; A can craft brass,
  B cannot; A hands B the second Blueprint; B uses it and can; B's Almanac chapter opens;
  the charter recipe works for a third player who has neither.
